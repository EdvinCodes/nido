# Phase 10 — PWA and notifications

## Goal

Nido becomes an app on the home screen: it opens instantly, works on the metro with no
signal, and taps you on the shoulder when a budget is about to break.

## Tasks

### 1. Installable PWA

1. `public/manifest.webmanifest`: name, short name, description in both locales, the warm
   dark theme and background colours, `display: standalone`, `orientation: any`, maskable
   icons at 192 / 512 / 1024, an Apple touch icon, and screenshots for both form factors so
   the install prompt shows a rich card.
2. App shortcuts for "Add expense" and "Scan receipt" so a long press on the icon jumps
   straight into capture.
3. A custom install prompt: capture `beforeinstallprompt`, show a tasteful banner after the
   user's third session, and provide iOS-specific instructions since Safari has no prompt.
4. Safe-area insets handled on all four edges; correct behaviour with the on-screen keyboard
   open; `theme-color` matching the active theme.

### 2. Service worker

Serwist (the maintained successor to Workbox's Next integration), configured explicitly
rather than by copying a template:

- App shell precached; navigation requests use a network-first strategy with an offline
  fallback page.
- Static assets: cache-first with a long expiry.
- API and data requests: stale-while-revalidate for reads, never cached for writes.
- Receipt thumbnails: cache-first with a size-capped LRU.
- A visible update flow — when a new version is waiting, show a toast offering to reload.
  A silently stale PWA is a support nightmare.

### 3. Offline capture

The one thing that must work with no connection: adding a transaction.

- The current period's transactions, categories, participants, and accounts are cached in
  IndexedDB (via `idb`) on every successful load.
- A transaction created offline is written to a local queue with a client-generated id and
  shown in the ledger with a "pending sync" marker.
- Background Sync flushes the queue on reconnect; where Background Sync is unavailable
  (Safari), flush on the next foreground.
- Server Actions are already idempotent on the client request id from Phase 02, so a
  double-flush cannot duplicate anything.
- Conflicts resolve last-write-wins per field, and any conflict is surfaced to the user
  rather than silently resolved.
- A clear connection status indicator, and honest copy about what does and does not work
  offline. Editing, deleting, and viewing analytics are read-only or unavailable offline,
  and the UI says so.

### 4. Web push

1. `nido.push_subscriptions` with RLS scoped to the user.
2. VAPID keys generated by `pnpm push:keys` and documented in `.env.example`.
3. A permission flow that asks in context — after a budget alert would have fired, not on
   first load — with a pre-prompt explaining what will be sent, so a denial is unlikely.
4. Edge Function `push-send` using `web-push`, called by the existing notification pipeline.
   Handle `410 Gone` by deleting the dead subscription.
5. Notification payloads carry a title, body, icon, badge, a deep link, and actions where
   useful ("View budget", "Mark as read"). Clicking focuses an existing window if one is
   open rather than opening a second.
6. iOS: push requires the PWA to be installed to the home screen. Detect and explain this
   rather than showing a permission button that cannot work.

### 5. Email notifications

With `RESEND_API_KEY` set, send email for the kinds the user has enabled. React Email
templates matching the design system, always with a plain-text alternative and a one-click
unsubscribe honouring the preference matrix. Without the key, email rows in the preferences
matrix are disabled with an explanation.

### 6. Preferences and quiet hours

`/s/[spaceId]/settings/notifications` becomes fully functional: the kind × channel matrix
with all three channels live, per-space overrides, quiet hours (during which push is
suppressed and queued for the next allowed window), and a "send test notification" button
per channel.

### 7. Mobile polish

- Pull to refresh on the ledger and dashboard.
- Haptic feedback on save and on destructive confirmations, where the Vibration API exists.
- Bottom sheets that respond to a drag handle with a real velocity-based dismiss.
- The FAB hides on scroll down and returns on scroll up.
- Keyboard-aware scrolling so the amount input is never hidden behind the keyboard.

## Acceptance criteria

- [ ] Lighthouse PWA audit passes every check on both Chrome and Safari.
- [ ] The app installs on Android and iOS and launches standalone with no browser chrome.
- [ ] With the network disabled, the app opens, shows the cached period, and accepts a new
      transaction; reconnecting syncs it exactly once.
- [ ] Flushing the offline queue twice creates no duplicates.
- [ ] A budget threshold crossed by one member delivers a push to the other within a minute.
- [ ] Clicking a push notification opens the correct screen and focuses an existing window.
- [ ] Quiet hours suppress push and deliver afterwards.
- [ ] Revoking notification permission degrades cleanly with no console errors.
- [ ] A service worker update shows the reload toast and applies on accept.
- [ ] `pnpm verify`, `pnpm test:db`, `pnpm test:e2e` pass, including a Playwright test that
      goes offline, adds a transaction, and comes back online.

## Out of scope

Native applications, widgets, Siri or Google Assistant integration, and SMS notifications.

## Verification

```bash
pnpm build && pnpm start
pnpm test:e2e   # includes the offline spec
```

Manual: install on a real phone, enable airplane mode, add an expense, re-enable, and
confirm it syncs once. Then have the other account cross a budget threshold and confirm the
push arrives.
